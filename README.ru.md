# Slovorez

[English](README.md) · **Русский**

**Slovorez** — нейросетевая библиотека для морфемной сегментации русского языка: разбивает слово на приставку, корень, суффикс и окончание (тот самый «разбор слова по составу»). Инференс идёт на CPU через ONNX Runtime — без GPU и тяжёлых зависимостей, — а ядро лексера написано на C++. Лёгкая модель (~0.69M параметров) делает библиотеку пригодной для продакшена и edge-сценариев.

## Возможности

- Морфемный разбор на классы: приставка, корень, суффикс, окончание, постфикс
- Инференс на CPU через ONNX, без GPU
- C++ токенизатор с привязками через pybind11
- Пакетная обработка файлов с кэшированием уже размеченных слов

## Быстрый старт

```python
from slovorez import Slovorez

model = Slovorez.from_pretrained("models/slovorez-test")
model.predict("Приставки и суффиксы выделяются автоматически.")
```

```python
 {'word': 'выделяются',    'morphemes': [Morpheme('вы', PREF, 0.93), Morpheme('дел', ROOT, 0.93), Morpheme('я', SUFF, 0.84), Morpheme('ют', SUFF, 0.79), Morpheme('ся', POSTFIX, 0.99)]},
 {'word': 'автоматически', 'morphemes': [Morpheme('автомат', ROOT, 0.73), Morpheme('ическ', SUFF, 0.80), Morpheme('и', SUFF, 0.76)]}]
```

Каждая морфема — это `Morpheme(текст, класс, уверенность)`.

Классы морфем:

| класс | значение |
|---|---|
| PREF | приставка |
| ROOT | корень |
| SUFF | суффикс |
| END | окончание |
| POSTFIX | постфикс |
| LINK | соединительная морфема (интерфикс) |
| HYPH | дефис |

В текст можно подавать любой язык — Slovorez извлекает и размечает только русские слова, сохраняя их порядок.

### Декодирование

По умолчанию предсказания декодируются жадным argmax. Передайте `use_viterbi=True` для декодирования Витерби со схемой BIES: оно запрещает недопустимые переходы меток и повышает согласованность границ:

```python
model.predict("...", use_viterbi=True)
```

## Качество

Slovorez (Sq NoRoPE, ~0.69M параметров) на тестовой выборке Revised RuMorphsLemmas, в двух режимах разбиения:

- **Random split** — словоформы разбиваются случайно; корни из теста могут встречаться и в обучении.
- **Root split** — разбиение по корням, корни теста не встречаются при обучении (OOV) — более сложный режим на обобщение.

| Сплит | F1 границ | Root F1 | Accuracy | Word Acc |
|---|---|---|---|---|
| Random | 95.95 | 91.77 | 95.22 | 80.51 |
| Root (OOV) | 91.83 | 83.59 | 90.12 | 64.32 |

*F1 границ — F1 по всем границам морфем; Root F1 — F1 по границам корней; Accuracy — посимвольная; Word Acc — доля полностью верно разобранных слов.*

## Производительность

Замеры на корпусе русской классической литературы: ~3,6 млн токенов всего, из них ~1,71 млн — русские слова (~150К уникальных словоформ); остальное — знаки препинания и нерусские токены, которые токенизатор пропускает. *Чистый инференс* прогоняет полный конвейер (C++ токенизатор → дедупликация → ONNX-инференс → запись JSONL) по ~150К уникальным формам; *реальный корпус* прогоняет весь корпус с кэшем `SeenIndex`, который по закону Зипфа превращает повторы в попадания в кэш (~91% попаданий здесь).

**Чистый инференс — ~150К уникальных словоформ (сл/с):**

| Конфигурация | 1 воркер | 4 воркера |
|---|---|---|
| CPU — Ryzen 7 5700X | ~13 200 | ~17 600 |
| GPU — RTX 5060 Ti | ~19 500 | ~23 000 |

**Реальный корпус — ~1,71 млн русских слов, один поток с кэшем (сл/с):**

| Конфигурация | Декодер | Пропускная способность |
|---|---|---|
| CPU — Ryzen 7 5700X | argmax | ~141 000 |
| CPU — Ryzen 7 5700X | Витерби | ~67 000 |
| GPU — RTX 5060 Ti (батч 2048) | argmax | ~246 000 |

### GPU (опционально, для опытных пользователей)

CPU — режим по умолчанию, рекомендуется.

Если вам всё же нужен именно CUDA-инференс:

```bash
pip install .[gpu]
```

Поддержка GPU предоставляется **как есть** и рассчитана на пользователей, которые сами управляют своим стеком CUDA/cuDNN. `onnxruntime-gpu` **не** включает CUDA и cuDNN — за совместимые рантайм-библиотеки и их наличие в пути поиска отвечаете вы. Начните отсюда:

- CUDA execution provider в ONNX Runtime: <https://onnxruntime.ai/docs/execution-providers/CUDA-ExecutionProvider.html>
- Установка и матрица версий ONNX Runtime: <https://onnxruntime.ai/docs/install/>

Если ваш стек CUDA/cuDNN не соответствует требованиям ONNX Runtime, ORT уходит в CPU-фолбэк. Проще всего избежать ручной возни с DLL, установив сборку PyTorch под той же мажорной версией CUDA, что и ONNX Runtime — тогда ORT автоматически переиспользует библиотеки CUDA/cuDNN из PyTorch.

## Как это устроено

Архитектура — Conv1D с разметкой последовательностей в схеме BIES (границы морфем как метки токенов). Лексер и токенизация реализованы на C++, инференс — через ONNX Runtime на CPU.
